# مجلس — مستشارك داخل الاجتماع (Powered by Claude)

تطبيق موبايل (PWA) بيسجّل الاجتماع من ميكروفون الموبايل، يفرّغ الكلام عربي لحظيًا مع فصل المتحدثين، ويبعته لـ Claude اللي:

- **أثناء الاجتماع**: يستنتج مين بيتكلم ودوره، يبني لوحة مواضيع بأهداف قابلة للقياس وحلول، ويكتب لك رأيه (خطر / سؤال لازم يتسأل / فرصة / حل) — وتقدر تسأله كتابةً في أي لحظة.
- **بعد الاجتماع**: ملخص، قرارات، خطة مهام بجدول زمني واعتماديات، مسودات إيميلات، وأجندة الاجتماع الجاي.
- **Google**: شيت المهام، محضر Docs، مواعيد على Calendar، وإرسال الإيميلات (بموافقتك على كل إيميل).
- **المتابعة**: شاشة بكل المهام المفتوحة/المتأخرة عبر الاجتماعات، شات مع Claude عن التنفيذ، وإيميل متابعة يومي اختياري. والاجتماع الجديد بيبدأ وClaude عارف المعلّق من اللي قبله.

## ليه مش Otter / Fireflies / Granola / Plaud؟

| عيب المنافسين | الحل هنا |
|---|---|
| ملخص **بعد** الاجتماع فقط — مفيش رأي وقت القرار | لوحة مستشار حيّة بتتحدث كل ~20 ثانية + سؤال مباشر لـ Claude |
| مبنيين لاجتماعات Zoom/Meet (bot بيدخل المكالمة) — ضعاف في الاجتماع الحضوري | الموبايل على الترابيزة هو الأساس، من غير bot |
| العربي ضعيف أو غير مدعوم (Otter ~6 لغات) | محرك تفريغ لحظي بيدعم العربي والـ code-switching مع الإنجليزي + Claude بيكتب بالعامية المهنية |
| تحديد المتحدث أضعف نقطة عندهم («Speaker 2») | Claude بيستنتج الاسم والدور من السياق ويذكر الدليل، وتصحيحك بضغطة بيتثبّت وما يتغيّرش |
| Granola ما بيحفظش الصوت — مفيش مراجعة | الصوت بيتحفظ على موبايلك كل 5 ثواني (ما بيترفعش لأي سيرفر) |
| قضايا تسجيل بدون علم الحاضرين وبصمات صوت (Otter, Fireflies) | تأكيد إعلام الحاضرين قبل التسجيل، ومفيش أي بصمة صوت بيومترية بتتخزن |
| المهام بتموت في الملخص | مهام بمسؤول وتاريخ واعتماديات + شيت + Calendar + متابعة يومية |
| إرسال تلقائي ومحتوى مش متراجع | كل الإيميلات مسودات؛ مفيش حاجة بتطلع غير بضغطة «إرسال» وتأكيد |
| اشتراك شهري لكل مستخدم وحدود دقائق | مفاتيحك أنت، بتدفع الاستهلاك الفعلي بس |
| التسجيل بيضيع لو الاتصال قطع | النص بيتحفظ على السيرفر أول بأول، إعادة اتصال تلقائية، واستكمال بعد قفل الصفحة |

## التشغيل

```bash
cd majlis
npm install
cp .env.example .env   # واملا المفاتيح
npm start              # http://localhost:8787
```

من غير مفاتيح التطبيق بيشتغل في **وضع تجريبي** (اجتماع مثال + ردود جاهزة) عشان تشوف التجربة كاملة.

### المفاتيح

| المتغير | منين | لازم؟ |
|---|---|---|
| `ANTHROPIC_API_KEY` | console.anthropic.com | نعم |
| `SONIOX_API_KEY` | console.soniox.com | نعم |
| `APP_PASSWORD` | كلمة سر تختارها | نعم عند النشر |
| `BASE_URL` | رابط التطبيق العام | نعم عند النشر |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google Cloud Console | للشيتات والإيميلات |
| `OWNER_NAME` / `OWNER_ROLE` | اسمك ودورك | يفضّل |

### ربط Google (مرة واحدة، ~10 دقايق)

1. [console.cloud.google.com](https://console.cloud.google.com) ← مشروع جديد.
2. **APIs & Services ← Library**: فعّل Google Sheets API، Google Drive API، Gmail API، Google Calendar API.
3. **OAuth consent screen**: External، وضيف إيميلك في **Test users**.
4. **Credentials ← Create ← OAuth client ID ← Web application**، وفي Authorized redirect URIs: `<BASE_URL>/auth/google/callback`.
5. حط الـ Client ID والـ Secret في `.env`، وافتح التطبيق ← الإعدادات ← «ربط حساب Google».

الصلاحيات ضيقة عمدًا: `drive.file` (الملفات اللي التطبيق بيعملها بس)، `gmail.send` (إرسال من غير قراءة)، `calendar.events`.

### النشر (عشان يشتغل على الموبايل)

الميكروفون بيشتغل على **HTTPS فقط**. أسهل طريق: Render ← New ← Blueprint ← الريبو ده (ملف `render.yaml` جاهز بـ disk دائم)، أو أي استضافة Docker:

```bash
docker build -t majlis . && docker run -p 8787:8787 -v majlis-data:/data --env-file .env majlis
```

بعدها افتح الرابط على الموبايل ← مشاركة ← «إضافة إلى الشاشة الرئيسية».

## التكلفة التقديرية (اجتماع ساعة)

- التفريغ الصوتي: حوالي 0.12$ (حسب تسعير Soniox المعلن).
- Claude: التحليل الحي ~120-180 استدعاء صغير (النص السابق بيتقري من الـ cache) + استدعاء نهائي واحد. تقدير مبدئي 1.5–4$ للساعة على `claude-opus-5-5` — قيسها على أول اجتماعين من لوحة Anthropic. لتقليل التكلفة غيّر `CLAUDE_MODEL=claude-sonnet-5-5`.

## حدود لازم تعرفها

- **الشاشة لازم تفضل مفتوحة**: المتصفح على iOS/Android بيوقف الميكروفون لو الشاشة اتقفلت. التطبيق بيمنع الشاشة تنام، ولو حصل انقطاع بتكمّل من نفس الاجتماع. التسجيل والشاشة مقفولة محتاج تطبيق native (المرحلة الجاية).
- **التعرف على الأشخاص**: فصل الأصوات آلي، لكن ربط الصوت بالاسم بيتم من السياق + تصحيحك، مش ببصمة صوت محفوظة بين الاجتماعات (قرار مقصود قانونيًا وتقنيًا في النسخة دي).
- **دقة العامية المصرية** لازم تتقاس على تسجيلاتك الفعلية (ضوضاء المكان وبُعد المتحدثين بيفرقوا). المحرك معزول في `public/audio.js` وسهل يتبدّل.
- **لم يُختبر مع الخدمات الحيّة بعد**: الكود اتختبر آليًا في الوضع التجريبي (API كامل + الواجهة على شاشة موبايل + شكل طلبات Google). أول تشغيل بمفاتيح حقيقية هو الاختبار الفعلي لـ Soniox و Claude و Google.
- مستخدم واحد (كلمة سر واحدة). التخزين ملفات JSON في `DATA_DIR`.

server/prompts.js  تعليمات Claude وشكل مخرجاته
server/google.js   OAuth + Sheets / Docs / Gmail / Calendar
server/board.js    دمج تحديثات Claude في لوحة الاجتماع
public/            واجهة الموبايل (PWA)
test/              npm test
